# Викторина - мини-приложение для Max

Мини-приложение для мессенджера [Max](https://max.ru) с реалтайм-викторинами: одиночная игра, игра против бота и мультиплеер с друзьями по коду комнаты.

Каждый владелец может развернуть собственный экземпляр на VDS и подключить своего бота Max.

## Возможности

- **Три режима игры**: одиночная, против бота, мультиплеер по коду комнаты (2+ игроков)
- **Категории и подтемы** - паки вопросов группируются по папкам (например «Медицина» → «Лечебное дело», «Военная медицина» и т.д.), можно играть по всему разделу сразу или по одной теме, вопросы выбираются случайно
- **Настраиваемое количество вопросов** - от 1 до размера выбранного пула, автоматически ограничивается сервером
- **Вопросы с медиа** - картинка и/или аудио у вопроса, а также картинка у отдельных вариантов ответа
- **Защита от читерства**: короткий таймер на ответ, у каждого игрока свой случайный порядок вариантов, детект переключения вкладки/потери фокуса, флаг подозрительно быстрых ответов, «sudden death» - если один игрок в мультиплеере уже ответил, у остальных остаётся не больше 5 секунд
- **Авторизация только через Max** - сервер проверяет криптографическую подпись `initData` (HMAC-SHA256 по схеме Telegram Mini Apps), играть напрямую в браузере нельзя
- **Профили и рейтинг** - ELO-рейтинг считается только для будущего режима подбора соперника (matchmaking), не для обычных игр с друзьями/ботом
- **Реконнект** - если игрок случайно закрыл приложение или потерял связь, у него есть 45 секунд на переподключение с восстановлением текущего вопроса и оставшегося времени
- **Админ-панель** - список игроков с рейтингом, бан/разбан (доступна по ID из `ADMIN_USER_IDS`)
- **Приглашение через Max** - шеринг кода комнаты через нативное окно Max, копирование кода в буфер

## Технологии

- **Backend**: Node.js (без фреймворков), нативный HTTP-сервер + [`ws`](https://github.com/websockets/ws) для WebSocket
- **Frontend**: чистые HTML/CSS/JS, без сборки и зависимостей
- **Хранилище**: вопросы - JSON-файлы на диске, профили игроков - `data/users.json` (не в git)

Сервер специально сделан лёгким - рассчитан на слабый VDS (1 ГБ RAM), потребляет ~17 МБ памяти в простое.

## Структура проекта

```
server/
  index.js     - HTTP-сервер, WebSocket-роутинг, паки вопросов, matchmaking-заготовка
  rooms.js     - игровая логика комнат (вопросы, таймеры, подсчёт очков, анти-чит)
  auth.js      - проверка подписи initData от Max
  store.js     - хранилище профилей игроков (рейтинг, баны)
  env.js       - загрузка .env (токен бота, админы)
public/
  index.html, style.css, app.js - клиент мини-приложения
  media/       - картинки/аудио для вопросов
questions/
  *.json                - паки вопросов верхнего уровня
  <категория>/*.json     - паки, сгруппированные по теме
  README.md              - как добавлять новые паки (шаблон, формат медиа)
```

## Развёртывание на VDS

Для работы нужны Node.js с поддержкой встроенного `fetch` (Node.js 20 или новее), npm, домен с HTTPS и собственный бот с мини-приложением в Max. Ниже пример для Linux с systemd и nginx. DNS домена должен указывать на ваш сервер, а порты 80 и 443 должны быть доступны извне.

1. Скачайте репозиторий и установите зависимости:

```bash
git clone https://github.com/f1est0/max-victorins.git
cd max-victorins/server
npm ci
cd ..
cp .env.example .env
```

2. В `.env` укажите токен своего бота и при необходимости числовые ID администраторов. Для обработки событий бота задайте случайный `WEBHOOK_SECRET`; не публикуйте его и токен. Файл `.env` не должен попадать в Git.
3. В `public/config.js` укажите `botUsername` без `@` для ссылок и приглашений. При необходимости задайте `supportProfileUrl`; без него кнопка поддержки скрыта. Эти параметры публичны, секреты в них хранить нельзя.
4. В настройках своего бота Max укажите HTTPS-адрес мини-приложения. При использовании вебхука настройте адрес `https://ВАШ-ДОМЕН/bot/webhook/ВАШ_WEBHOOK_SECRET` для событий бота.
5. Запустите сервер для проверки командой `cd server && npm start`. Он слушает только `127.0.0.1:3000`; `PORT` можно задать переменной окружения процесса. Проверка доступности: `curl http://127.0.0.1:3000/healthz`. Для игры нужна действительная подпись Max и правильный токен: напрямую в браузере играть нельзя.

### Сертификат Минцифры для API Max

Для исходящих запросов бота к `platform-api2.max.ru` Node.js должен доверять корневому сертификату Минцифры. Получите актуальный корневой сертификат на [Госуслугах](https://www.gosuslugi.ru/crt), сохраните его на сервере в формате PEM, например `/etc/ssl/certs/russian-trusted-root-ca.pem`, и убедитесь, что файл доступен для чтения пользователю службы. Рекомендация добавить сертификат в доверенные приведена в [документации Max](https://dev.max.ru/docs-api/methods/POST/subscriptions/).

Перед запуском передайте путь через `NODE_EXTRA_CA_CERTS`: эта переменная расширяет список доверенных сертификатов Node.js и считывается при запуске процесса. Например:

```bash
cd server
NODE_EXTRA_CA_CERTS=/etc/ssl/certs/russian-trusted-root-ca.pem npm start
```

Это настройка доверия для соединения приложения с API Max. HTTPS-сертификат своего домена для nginx настраивается отдельно. Подробнее о переменной - в [документации Node.js](https://nodejs.org/download/release/latest-v20.x/docs/api/cli.html#node_extra_ca_certsfile).

Пример `/etc/systemd/system/quiz-app.service`: замените пользователя и путь на свои абсолютные значения.

```ini
[Unit]
Description=Max quiz
After=network.target

[Service]
Type=simple
User=quiz
WorkingDirectory=/opt/max-victorins/server
Environment=PORT=3000
Environment=NODE_EXTRA_CA_CERTS=/etc/ssl/certs/russian-trusted-root-ca.pem
ExecStart=/usr/bin/node index.js
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

Пользователю службы нужны права чтения проекта и записи в `data/` в корне проекта. Запустите службу: `sudo systemctl daemon-reload && sudo systemctl enable --now quiz-app`.

Пример nginx после выпуска сертификата для своего домена (замените пути к сертификату и имя домена):

```nginx
server {
    listen 443 ssl;
    server_name example.com;
    ssl_certificate /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
```

Настройте также перенаправление HTTP на HTTPS и проверьте конфигурацию nginx перед перезапуском. Профили и пользовательские наборы хранятся в `data/`; сохраняйте резервную копию этой папки при обновлениях и переносе сервера.
